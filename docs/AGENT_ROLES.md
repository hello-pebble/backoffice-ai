# 담당 에이전트 역할과 소유 영역

## 기본 원칙

각 에이전트는 자신에게 할당된 폴더와 명시된 통합 지점만 수정한다. 다른 담당 영역의 직접 수정이 필요하면 `integration-agent`에게 API 계약 또는 작업 순서를 요청한다.

| 에이전트 | 소유 영역 | 책임 | 수정하지 않는 영역 |
|---|---|---|---|
| `frontend-agent` | `frontend/` | 화면, 사용자 입력, 로딩·오류·빈 상태, API 결과 표시 | `backend/`, Python 자동화 로직 |
| `backend-agent` | `backend/`, API 계약 | Kotlin API, DB, 인증, Gmail·주식 등 외부 연동, AI 실행 이력 | 화면 스타일, Python 작업 내부 로직 |
| `automation-agent` | `automation/` | AI 생성, 블로그·콘텐츠·영상 자동화, 작업 재시도 | DB 직접 접근, 화면 파일 |
| `integration-agent` | `config/*.example`, `docs/`, 배포 설정, API 계약 | 서비스 연결, 환경 변수, 배포 순서, API 호환성, 릴리스 점검 | 기능별 화면·업무 규칙의 단독 변경 |

## 작업 요청 형식

작업을 요청할 때는 아래 정보를 함께 제공한다.

```text
담당: frontend-agent
목표: 콘텐츠 스튜디오 결과 카드에 복사 버튼 추가
수정 가능 영역: frontend/
연결 API: POST /api/content-packages
완료 조건: 모바일·빈 상태·오류 상태에서 정상 표시
```

## 담당별 완료 조건

### frontend-agent

- API 성공·로딩·실패·빈 상태가 모두 화면에 표시된다.
- API 키와 OAuth 비밀값을 브라우저 코드에 넣지 않는다.
- 새 API 필드는 기존 화면과 호환되게 처리한다.

### backend-agent

- 요청·응답·오류 형식이 문서화된다.
- 외부 API 실패와 재시도 가능 여부를 기록한다.
- AI 실행이면 모델·토큰·비용·사용 도구를 `AI 운영 센터`에 남긴다.

### automation-agent

- 실제 외부 발행은 검토 승인 전에는 실행하지 않는다.
- 장시간 작업은 상태를 남기고 중복 실행에도 안전해야 한다.
- 결과 파일은 객체 저장소 또는 API 경로로 전달한다.

### integration-agent

- 개발·스테이징·운영 환경 변수를 분리한다.
- 화면, API, 워커가 함께 바뀌면 API → 워커 → 화면 순서로 배포한다.
- 비밀값·개인 데이터·생성 결과물이 Git에 포함되지 않았는지 확인한다.

## 추가 역할 도입 기준

| 역할 | 도입 시점 | 책임 |
|---|---|---|
| `qa-agent` | 기능과 외부 연동이 늘어날 때 | 사용자 시나리오·회귀 테스트, 릴리스 점검 |
| `security-agent` | Gmail·Meta·YouTube OAuth를 운영에 연결할 때 | 권한 범위, 토큰 보관, 비밀값·보안 점검 |
| `data-agent` | PostgreSQL과 성과 분석을 시작할 때 | 데이터 모델, 마이그레이션, 지표 품질 |
| `stock-agent` | 국내 주식 기능을 실제 운영할 때 | 시세 수집, 관심 종목, 알림 후보, 데이터 신선도 |

## 주식 에이전트 원칙

`stock-agent`는 기본적으로 **정보 조회와 알림만** 담당한다. 매수·매도 주문, 투자 판단, 자동 거래는 범위에 넣지 않는다.

- 입력: 관심 종목, 보유 여부, 알림 기준
- 도구: 토스증권 Open API 또는 허가된 시세 API
- 출력: 현재가, 등락률, 장중/장마감 구분, 마지막 갱신 시각, 알림 후보
- 기록: 조회 시각, 데이터 출처, API 오류, 새로고침 상태
- 화면: CEO Office의 `시장·메일`과 AI 운영 센터에 표시

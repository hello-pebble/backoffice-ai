# 분리 배포 환경 개발 규칙

## 적용 범위

이 저장소는 하나의 저장소를 사용하지만, 다음 세 구성 요소를 독립적으로 배포한다.

| 구성 요소 | 위치 | 배포 대상 | 책임 |
|---|---|---|---|
| 웹 화면 | `frontend/static/` | Vercel | 사용자 화면, 입력 검증, API 호출 |
| 업무 API | `backend/` | Cloud Run | 업무 규칙, 인증, 외부 API 연동, DB 접근 |
| 자동화 워커 | `modules/`, `utils/`, `main.py` | Cloud Run Worker/VM | 장시간 AI·영상·블로그 자동화 |

## 절대 경계

1. 화면은 DB·OAuth 비밀값·외부 API 키에 직접 접근하지 않는다.
2. 화면은 공개된 Kotlin API만 호출한다.
3. Python 워커는 화면 파일이나 브라우저 세션에 의존하지 않는다.
4. Python 워커의 결과는 API 또는 DB·객체 저장소를 통해 전달한다.
5. Cloud 환경에서 `data/` 로컬 파일은 영구 저장소로 사용하지 않는다.
6. 모델 호출·영상 렌더링·외부 발행처럼 오래 걸리는 일은 API 요청 안에서 끝내지 않고 작업 큐/워커로 보낸다.

## 변경 순서

여러 서비스에 영향을 주는 기능은 다음 순서를 지킨다.

```text
1. API 계약 설계
2. Kotlin API 구현 및 검증
3. 화면 연결
4. 워커 연결(필요한 경우)
5. 스테이징 통합 확인
6. 운영 배포
```

API 변경을 먼저 배포해도 기존 화면이 깨지지 않게 한다. 필드를 제거하거나 의미를 바꾸는 변경은 새 버전 엔드포인트 또는 호환 기간을 둔다.

## API 계약 규칙

- 모든 API는 `/api` 아래에 둔다.
- 새 응답 필드는 추가만 허용하며, 기존 필드 삭제·이름 변경은 호환 기간 뒤에 한다.
- 요청·응답 모델, 오류 코드, 권한 요구사항을 PR에 적는다.
- 화면은 오류 응답을 그대로 노출하지 않고 사용자용 안내 문구로 바꾼다.
- 외부 연동 실패는 재시도 가능 여부와 마지막 오류를 AI 운영 센터 또는 실행 이력에 남긴다.
- 화면과 API의 개발·스테이징·운영 주소는 환경 변수로만 연결한다.

## 데이터와 파일 규칙

- 개발 데이터는 로컬 JSON을 사용할 수 있으나 운영 데이터는 PostgreSQL에 저장한다.
- 이미지·음성·영상은 객체 저장소에 저장하고, DB에는 URL·상태·메타데이터만 저장한다.
- API 키, OAuth token, Gmail/Meta/YouTube 인증 정보는 서버 비밀 설정에만 둔다.
- `*.example` 파일에는 키 이름만 두고 실제 값은 넣지 않는다.

## AI·자동화 규칙

- 에이전트 작업은 `대기 → 실행 중 → 성공/실패` 상태를 가진다.
- 생성 결과는 자동 발행하지 않는다. 기본 상태는 `검토 대기`다.
- AI 실행마다 모델, 입력·출력 토큰, 예상 비용, 도구, 결과 요약을 기록한다.
- 로컬 Ollama는 개발·테스트 전용으로 간주한다. 운영에서 사용하려면 인증된 별도 모델 서버를 둔다.
- 재시도는 멱등성을 보장해야 하며, 같은 콘텐츠를 중복 발행하지 않아야 한다.

## 서비스별 검증

| 변경 영역 | 최소 확인 |
|---|---|
| `frontend/static/` | API 실패·로딩·빈 상태가 사용자에게 이해되는지 확인 |
| `backend/` | Kotlin 컴파일 및 변경 API 응답 확인 |
| Python 자동화 | 실제 발행 없이 안전한 입력으로 실행 확인 |
| DB 변경 | 마이그레이션, 기존 데이터 호환, 롤백 방법 확인 |
| 외부 API | 권한 부족·속도 제한·실패 시 동작 확인 |

## 배포 기준

- 화면 변경만 있으면 Vercel 배포만 한다.
- API 변경만 있으면 Cloud Run API만 배포한다.
- 워커 변경만 있으면 워커만 배포한다.
- 여러 구성 요소가 함께 바뀌는 경우에는 API를 먼저, 워커를 다음, 화면을 마지막에 배포한다.
- 운영 배포 전 스테이징에서 같은 환경 변수 구조와 API 계약을 확인한다.

## PR 완료 조건

- [ ] 변경한 배포 대상이 명확하다.
- [ ] 다른 구성 요소와의 API 계약 영향이 적혀 있다.
- [ ] 비밀값·개인 데이터·로컬 실행 결과가 포함되지 않았다.
- [ ] 필요한 최소 검증을 통과했다.
- [ ] AI·자동화 기능이면 실행 이력과 검토 대기 흐름이 있다.
- [ ] 배포 순서와 롤백 방법이 필요한 경우 PR에 적혀 있다.

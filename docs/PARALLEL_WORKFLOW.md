# 기능은 API 계약을 먼저 합의한 뒤 담당 에이전트가 병렬로 개발한다.

| 단계 | 담당 | 규칙 | 결과값 |
|---|---|---|---|
| 1. 작업 분할 | `integration-agent` | 기능을 화면·API·자동화 작업으로 나누고, 수정 가능 폴더를 지정한다. | 담당별 작업 카드 |
| 2. 계약 합의 | `backend-agent` + 관련 담당 | 요청·응답·오류·작업 상태를 먼저 정한다. | API 계약 |
| 3. 병렬 구현 | `frontend-agent`, `backend-agent`, `automation-agent` | 서로의 소유 폴더를 직접 수정하지 않고 동시에 작업한다. | 담당별 변경 사항 |
| 4. 완료 신호 | 각 담당 | 변경 파일, 검증 결과, 필요한 환경 변수, 남은 의존성을 보고한다. | 작업 완료 보고 |
| 5. 통합 확인 | `integration-agent` | API 연결, 환경 변수, 배포 순서, 스테이징 동작을 확인한다. | 통합 검증 결과 |
| 6. PR 병합 | `integration-agent` | 모든 담당 결과를 확인한 뒤 `develop` PR로 병합한다. | 병합 가능한 PR |

## 병렬 실행 가능 조건

| 가능 | 보류 |
|---|---|
| API 계약이 확정된 화면·API 구현 | 요청·응답 형식이 아직 정해지지 않은 기능 |
| 독립적인 Python 자동화 작업 | 같은 파일을 둘 이상이 수정해야 하는 작업 |
| 문서·테스트·화면 개선 | DB 구조와 API 모델을 동시에 바꾸는 작업 |
| 기존 API를 소비하는 화면 변경 | 외부 OAuth 권한·비밀값이 필요한 작업 |

## 작업 요청 템플릿

```text
기능: 유튜브 쇼츠 생성
목표: 원본 콘텐츠에서 쇼츠 대본과 작업 상태를 만든다.
API 계약: POST /api/shorts, GET /api/shorts/{id}

[frontend-agent]
- 수정 가능: frontend/
- 완료 조건: 입력·진행·성공·실패 화면 표시

[backend-agent]
- 수정 가능: backend/
- 완료 조건: 쇼츠 작업 API와 상태 저장

[automation-agent]
- 수정 가능: modules/, utils/, run_*.py
- 완료 조건: 대본 생성과 결과 상태 전달

[integration-agent]
- 수정 가능: config/*.example, docs/, 배포 설정
- 완료 조건: 환경 변수·API 연결·스테이징 확인
```

## 중단과 동기화

- 계약이 바뀌면 구현을 계속하지 않고 `integration-agent`에게 알린다.
- 같은 파일 수정이 필요하면 한 담당만 수정하고, 나머지는 변경 요청으로 전달한다.
- 외부 발행·OAuth·DB 마이그레이션은 병렬 실행 전 승인과 배포 순서를 확정한다.
- 통합 전에는 각 담당이 독립 검증을 마쳐야 한다.
